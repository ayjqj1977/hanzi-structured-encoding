# 结果口径总表

这个仓库里出现过几组 PPL 数字，常被读成互相矛盾。它们来自**不同实验批次、不同模型族、不同评估方式**，不能直接横比。本表把"数字—模型—步数—评估口径"对齐，供引用时核对。

## PPL 对照

| 模型 / 组 | 输入 | 训练步数 | PPL | 来源 | 评估口径 |
|---|---|---|---|---|---|
| V6 纯 34 维 | 34 维结构特征（冻死） | — | 59.56 | 近三个月记录 | 100 篇短文，seq_len=64 |
| V10 34 冻死 + 64 | 34 冻死 + 64 可训 | 50,000 | 18.37 | v10 日志 | 训练日志 / 本地测试 |
| V12 34 冻死 + 64 | 34 冻死 + 64 可训 | 100,000 | 10.07 | 近三个月记录 | 同一 100 篇短文 |
| 消融：96 纯随机 | 96 维可训随机 | 100,000 | **9.66** | 近三个月记录 | 同一 100 篇短文 |
| PointMatrix Spatial | HZK32 32×32 点阵 + 卷积 | 50,000 | 14.12 | spatial 曲线 | 同源测试集 |
| PointMatrix（HZK32 报告） | 32×32 点阵 | 45,000 | 14.20 | HZK32 报告 | 该报告口径 |
| CNN 5-Stream | 5 路 CNN 可训 + 5 特征 | 33,480 | **13.55** | HZK32 报告 | 该报告口径 |

## 为什么 13.55 与 9.66 不能直接比

- `13.55` 是 HZK32 报告里 **CNN 5-Stream** 的结果，步数 33,480，评估在该报告设定的语料与测试方式下；
- `9.66` 是消融实验里 **96 维纯随机** 的结果，步数 100,000，评估用同一套 100 篇短文、seq_len=64；
- 模型族、训练步数、评估集都不同。HZK32 报告的"CNN 5-Stream 最优"只在该报告的三组对照内成立，不等于"全项目最优"。

## 字形区分力

| 模型 | 区分力 | 说明 |
|---|---|---|
| PointMatrix Spatial 35K | 17–18x | 10 对焦点形近字，余弦 / 随机基线 |
| PointMatrix PointNet 45K | 17.1x | 同上 |
| 云端训练 18 维 | 3.13x | 嵌入分散，弱字形信号 |
| NeuroGlyph34 共享 npy | 1.07x | 嵌入坍缩成窄锥 |
| 18 维仅四角号码 | 3.35x | 子集消融，非训练嵌入 |

## 一处需要回原始日志核对的数字

V6 的"形近 17/18"与跨模型复核的"1.07x"：

- 17/18 很可能测的是 **34 维手工输入特征**本身的形近分离；
- 1.07x 测的是 **训练后的字符嵌入**（`embedding_matrix.npy`，六个目录共享同一份）。
- 两者不是同一层。若 17/18 实际来自模型内部表示，则与复核冲突，需要回原始日志确认。

**引用建议**：写"某模型在某口径下"时，把步数与评估方式一起写；不要只写一个 PPL 数字。
